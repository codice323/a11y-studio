# A11y Studio 跨网站修复验证

## 验证设计

以五个原创合成网页模拟企业官网、电商目录、新闻文章、教育站点和表单系统。它们是本次审查编写的独立授权样例，与内置开发示例分开。测试通过 ZIP 导入，浏览器访问快照与导出文件。样例未经公共网站抓取，也没有复用公共网站素材。

每条任务在运行前标注目标元素、预期无障碍语义和一个无缺陷对照。标注保存在测试侧，不进入上传网页或模型输入。图片均为测试侧绘制的原始像素。企业页、新闻页和电商页分别覆盖 PNG、GIF 和 WebP 视觉请求，电商对照另加载 JPEG，且用 `picture` 和相对资源路径。结构覆盖原生表单、无 ID 字段、嵌套文本、重复商品卡片、空图标按钮和多层目录中的外部 CSS。HTML 入口包含 `index.html`、嵌套入口及非默认文件名。

每条任务从同一页面的 V0 开始。生产扫描提供 axe 与行为证据，通过统一的提案、审批、复测和导出 API。测试审批代表测试人员在受控样例中的确认操作。独立 Chromium 再打开导出的结果，读取 CDP 无障碍树、原生标签绑定、浏览器实际颜色和键盘 Tab 后的焦点样式。修复成功要求生产复测通过、目标通过预先标注的独立语义断言、配对反例保持不变，且没有新增确定违规。图片文本还需对照原图主题，按钮需要匹配作者标注的实际用途。样本中的单个关键词仅作为最低主题断言，不能验证替代文本的所有细节。

## 审查结论

| 类别 | 代码性质与覆盖边界 |
|---|---|
| 示例载入 | `apps/api/import.ts` 和 `apps/api/server.ts` 的三个内置示例名称及目录是演示适配。ZIP 和 URL 路径独立。未发现检测或修复分支依赖「慢绿生活」、`plant.png`、`#email` 或 `.description`。 |
| 通用检测 | axe 按规则标签扫描。Chromium 采样实际 Tab、焦点与语义树，行为和 ARIA 线索单列待复核。截断、可见范围和静态快照限制会影响覆盖。 |
| 通用规则生成 | 字段类型、自动填充语义、紧邻可见文字生成原生标签计划。图片 Alt 和旧式属性补丁使用确定性的源位置编译器。固定规则 ID、字段类型映射和聚焦样式模板是产品支持范围。 |
| 模型决策 | 视觉请求根据实际资源或浏览器截图建议 Alt 与图片用途。源码 Agent 使用目标 DOM、局部源码和 WCAG 证据规划按钮命名、颜色、焦点样式和引用关系，并可根据隔离复测反馈调整。表单结构线索充足时直接用规则生成，耗费零模型请求。 |
| 修改与回归 | 修改局限于唯一可定位的源码节点及入口页链接的本地样式。源码编译器限制操作和文件范围，核对哈希并在隔离副本重跑检测。用户确认后再次验证才切换版本。 |

## 发现并修正的通用问题

- 浏览器可能将纯包装 `span` 视为无语义节点，仍将其文本暴露给辅助技术。对比度校验现在会用 Chromium 可访问快照核实可见文本。按钮、标签和 ARIA 修复仍须验证目标语义节点本身。
- 三个悬空 `aria-labelledby` 引用在首轮出现在 axe 的待复核结果，缺少可进入的修复入口。浏览器现在单独检查受采样元素的 `aria-labelledby` 和 `aria-describedby` 是否指向缺失的 ID，并从「V2 检测证据」提供复核修复入口。复测要求引用问题消失且名称或说明可解析。该入口不计为确定 WCAG 违规。

### 语义核对与剩余失败

- 四个表单任务均使用真实原生 label；含无 ID 的课程搜索字段和一个用途模糊的普通输入。后者没有猜测文案，人工提供「预约登记编号」后才成功。
- 三条对比度修复实际写入外部 CSS。电商页的样式同时涉及 HTML 标记和 CSS 文件；独立实测修复后的对比度分别为 15.34:1、15.34:1、7.00:1。
- 三条 ARIA 修复分别恢复「收藏文章」「Download lesson notes」「保存并提交预约」。三条焦点修复均由实际 Tab 到达目标，并测到可见轮廓。
- PNG 桥梁和 WebP 台灯通过图片用途与主题复核。新闻页 GIF 已读取真实像素，但模型把作者标注的轨道交通图判成公交车，测试没有应用该建议。这个合成图本身也存在辨识歧义，单例不足以判定 GIF 格式整体表现。
- 电商加购按钮需提供明确文案才应用。表单页空白提交按钮没有得到可直接使用的候选，因视觉与局部上下文均未确认业务动作，保留待人工。

完整逐案数据位于 `data/cross-site-repair/results.json`，含每条修改的 Diff、模型用量、失败原因、检测通道和前后证据。可用 `results.csv` 筛选。首轮数据另存为 `baseline-results.json`。模型输出可能波动。

## 限制

结果适用于这一组静态样例。未覆盖登录、真实业务提交、脚本驱动控件的打开状态、Shadow DOM、跨框架焦点、任意页面结构重写、复杂背景对比度或所有 ARIA 属性。桌面 Chromium 的 Tab 和无障碍树证据也无法替代真实屏幕阅读器和用户测试。焦点规则是待复核线索。图片、按钮及 ARIA 的用途、描述措辞和关联对象仍需人工审核。所有应用均经过确认，因此本次没有评估无人审批部署。

## 复现

在项目根目录运行。需要 Node、Google Chrome 或配置 `CHROME_PATH`、macOS `sips`（生成 GIF）和有效 DeepSeek 配置。脚本启动临时数据库，逐案写入 JSON，记录模型用量但不写入密钥或请求内容。本次最终回归的 typecheck、build 和 17 项测试均通过。

```sh
node scripts/cross-site-repair.mjs /absolute/path/to/.env data/cross-site-repair
npm run typecheck && npm run build && npm test
```
