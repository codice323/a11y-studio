# 自动探索 V2.6.1

静态文档先完成入口采集。只有同一静态文档已成功采集，且导航不带片段时，才跳过该次导航。报告标记这些跳过。SPA 仍执行真实导航。状态指纹包含可见控件及其 ARIA 状态，Tab 路径也记录焦点。重放在推进前检查连续两次 DOM 采样，短暂的浏览器关闭或不稳定状态可在剩余预算内重试一次。

正式账号默认使用确定性模式。管理员配置既有 AI 凭据及 `A11Y_EXPLORER_AI_CALLS` 后，工作台会显示可选的 DeepSeek 排序。该额度最多 10 次，每个进程累计，每任务最多 1 次。模型只接收候选序号、动作类型、角色和导航标志。它的返回只能提升一个候选的队列优先级。现有候选检查、重放检查和任务预算继续适用。非法序号和超时回退到确定性顺序。记录请求数、耗时、令牌数及回退次数。

## 动态行为证据

| 行为 | Chrome 样本与证据 |
|---|---|
| 菜单展开和关闭 | React `Schedule` 展开后可见控件进入 AX 树。关闭返回已知状态，操作边仍保留 |
| 弹窗与焦点恢复 | `Ticket terms` 打开后捕获焦点未进入。关闭路径记录焦点未返回触发控件，保留为待复核 |
| 标签切换 | `Tomorrow` 路径的 AX 树出现 `Tomorrow afternoon` |
| 表单前端校验 | `Check availability` 执行原生校验并记录错误关联待复核。等价 DOM 的操作边链接到已知采集状态 |
| SPA 路由 | 实际导航到 `/tickets`、`/visit` 和独立样本的 `/dispatch` |
| 键盘焦点 | 弹窗内执行 Tab，记录实际焦点变化和焦点丢失待复核 |

在两组折叠的开发扩展示例上，确定性和模拟排序均覆盖 3/3 页、2/2 个标注交互。确定性执行 11 次尝试、5 次重复，模拟排序执行 12 次尝试、6 次重复。模拟请求 1 次、约 2 ms，测试令牌计数 40 输入、5 输出，外部请求 0 次、费用 0。模拟返回仅验证排序机制，真实 DeepSeek 的覆盖率、延迟与费用尚无测量。

Vue 源码项目当前受既有 React 工程导入器限制。媒体用例覆盖播放器所在页面和原生折叠交互。媒体播放、直播内容、跨站导航、写入性操作和仅通过超过采样窗口的延迟变化可达的状态仍缺乏覆盖。
