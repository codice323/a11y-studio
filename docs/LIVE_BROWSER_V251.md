# V2.5.1 实时浏览器滚动与界面

## 根因与实现

V2.5 的预览监听器每次收到 wheel 都尝试立即提交操作。上一请求在途时，请求锁会丢弃后续事件。接收的滚动进入通用动作链，两侧分别等待页面稳定，再采集无障碍树、控件和 JPEG。更新中提示位于正常文档流，反复显示和收起会移动预览。浏览器采样复现了预览位置跳动，没有采样到图片不可用。普通滚动并未重新创建 Chrome 会话。

V2.5.1 只在两块预览监听垂直滚轮，把输入合并成有序批次。单请求在途，下一批至少等待 45ms。Playwright 在实际网页中命中指针下可滚动的容器，在允许滚动链时才查找外层容器。同步开启时，另一侧按唯一 ID 或结构选择器匹配容器并执行一次绝对位置滚动，不在对侧产生滚轮事件。同步关闭时只改变源侧。方向键和翻页键可在预览聚焦时滚动，触屏在预览内使用纵向拖动。

滚动走独立轻量路径。DOM 没有变化时复用无障碍树和控件数据；位置及 DOM 都未变化时不生成截图；捕获结果与上次相同时不重传 JPEG。新画面解码后才替换旧图。操作串行，检查会话及递增修订号。切换版本或关闭时清空待处理滚动，旧响应不能替换新会话。画面更新时不会拿上一帧的坐标直接点击下一帧。

顶部保留版本、同步、刷新、两侧检测、关闭及更多操作。Tab、Esc、语义控件、测试输入和独立缩放移入折叠区。动态证据与差异按需展开，加载提示保留固定位置。诊断工作区继续使用现有布局和修复流程。

## Chrome 对照测量

Chrome 157.0.8103.39，浏览器窗口 1440×1000，两侧网页视口 900×700。基线为 `a0c6310` 加测量用的截图计时；在同一 React 工程、路由及两侧版本上，用 Playwright 分别发送 40 次 12px 滚轮输入。截图耗时为各侧截图调用耗时之和除以截图数。画面延迟为首个 wheel 到首个更新图片解码完成。空白计数用逐帧图片可用性采样，属于代理指标。

| 指标 | V2.5 | V2.5.1 |
|---|---:|---:|
| 到达预览的滚轮事件 | 40 | 40 |
| 后端滚动请求 | 6 | 18 |
| 两侧截图生成次数 | 12 | 36 |
| 实际传输的图片数 | 12 | 20 |
| 两侧实际滚动 | 72px | 480px |
| 每 100px 传输图片数 | 16.7 | 4.2 |
| 单张截图平均耗时 | 17.2ms | 17.2ms |
| 首帧更新延迟 | 235.2ms | 91.4ms |
| 预览框纵向位置波动 | 38px | 0px |
| 采样到的图片不可用帧 | 0 | 0 |
| 两侧最大同步位置差 | 0px | 0px |
| 工作台位置变化 | 0px | 0px |

旧版多数输入未执行，所以旧版总截图数较少。新版完整执行这批输入，实际传输按移动距离归一后下降。另执行 160 次输入的连续测试，共 76 次后端滚动，最终两侧均回到 480px，没有图片不可用样本，也没有重开会话。滚到边界不变时的操作生成零张截图。独立的切换版本测试中，旧会话的在途滚动被关闭打断，未观察到旧画面覆盖新会话。稳定会话的对照测试中没有过期帧交付。Chrome 测试使用合成输入序列，未测物理触控板和触屏硬件。现有 JPEG 回传架构仍有传输和解码延迟。

## 复现

```sh
npm run typecheck
npm run build
npm test
A11Y_SCROLL_BENCH=1 A11Y_SCROLL_STRESS=1 A11Y_LIVE_EVIDENCE=/tmp/live-scroll node --import tsx --test tests/live-comparison-e2e.test.ts
```

默认测试使用 Mac Chrome，可用 `CHROME_PATH` 指定兼容浏览器。证据文件来自隔离的测试账号和数据库。

## 回归结果

类型检查、生产构建及 35 项回归通过。Chrome 实时专项验证了双侧滚动、内层容器、边界零截图、移出后工作台滚动、刚滚动后的点击导航、滚动中版本切换与关闭、跨账号拒绝、模态和表单、V2.4 行为判定、Agent 补丁审核与同状态复测。真实 Chrome 和隔离网站实例用于全部浏览器操作，测试 Agent 使用本地模拟模型。
