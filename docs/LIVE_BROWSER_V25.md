# V2.5 双侧实时浏览器与动态修复验证

## 运行与隔离

实时工作区沿用项目版本选择，默认左侧为原始版本 V0，右侧为当前版本。每侧启动独立的沙箱 Chrome 进程和非持久化上下文，加载自己的项目版本。画面是浏览器视口的截图，用户操作由 Playwright 实际执行，随后重新获取画面、路径、焦点和无障碍树。会话绑定项目和当前认证会话，五分钟过期。显式关闭会等待两侧浏览器退出，退出账号也会终止对应会话。

浏览器只接受隔离副本的本地 GET 请求。上下文无用户 Cookie，禁止外部连接、WebSocket、下载和业务表单提交。文本控件只填入固定测试值，表单通过原生校验 API 测试。页面截图遮盖文本输入区域。浏览器环境不会继承项目站点外的认证会话。

| 导入方式 | 可执行的操作 | 边界 |
|---|---|---|
| 受支持的 React/Vite 源码工程 | 路由、菜单、标签、弹窗、允许的输入与原生校验、Tab、滚动与缩放 | 受本地构建和网络隔离约束，不能执行需要真实后台或支付等副作用的流程 |
| HTML、ZIP、静态 URL 和渲染 URL 快照 | 已导入页面之间的本地导航、浏览器原生控件、Tab、滚动与缩放 | 原网站脚本不执行。渲染 URL 仅保存已经采集的状态 |

缩放作用于 Chrome 中的页面布局，范围为 75% 到 150%。它用于核对布局变化，无障碍缩放与重排条款仍需单独验证。

## 同步与检测

源侧点击坐标只用于命中源侧控件。目标侧独立查找唯一的无障碍角色与名称，并核对可用的稳定 DOM ID、元素类型、链接目的地和表单行为。系统记录每侧的执行结果。同步确认要求两侧实际执行，并比较路由、模态、校验与本次操作造成的控件状态变化。滚动由后端发出一次目标滚动，不会在两侧循环。若目标缺失、歧义或状态无法匹配，保留已执行的一侧，显示失配原因。可关闭同步，独立查看差异。

实时动作复用 V2.4 动态判定。模态焦点未进入与 Tab 移到模态外分别是独立确认异常。ARIA 展开、错误关联、重复 Tab、失焦、焦点恢复、实时区域更新和路由提示按观测或待复核记录。手动扫描保留当前版本、路由、操作结果、焦点、DOM、计算样式、AX 快照、截图和 axe-core 规则结果。未执行的操作没有检测证据。完整键盘路径、读屏播报和触屏体验需要人工核查。

两侧按相同路由和可核对的操作序列展示问题增减与名称、角色差异。扫描失败在对应侧显示原因，并可随当前检测证据下载。成功证据写入原有实时报告表，无需 SQLite 迁移。

## 实时问题到源码修复

当前版本的源码工程中，实时扫描发现的可定位原生按钮命名问题可转入诊断工作台。服务端只接受当前会话自己执行的短序列，最多六步，在全新隔离浏览器复现同一路由、问题及源码定位后保存证据。过期扫描、无法重放的动作、缺失源码定位以及历史版本均不能直接生成补丁。缩放和原生 summary 操作暂不进入此修复重放配方。

Agent 读取重放获得的局部无障碍快照、操作及焦点证据，给出建议。人工核对补丁后才应用。预检和应用都会重建候选副本、重放操作序列、复测语义和回归。复测未通过时保留当前有效版本。焦点和 ARIA 行为异常可以查看证据，V2.5 的实时入口只自动生成受支持的按钮命名修复。

## 复现

```sh
npm run typecheck
npm run build
npm test
npm run test:campus
A11Y_LIVE_EVIDENCE=/path/to/private-output node --import tsx --test tests/live-comparison-e2e.test.ts
```

使用 Mac 上的 Chrome 或用 `CHROME_PATH` 指定 Chromium。专项包含校园 ZIP、带路由与异常状态的 React 工程，以及独立的博物馆预约 React/Vite 工程。后者从实时发现弹窗里的无名按钮开始，检查 Agent 确实收到重放证据，再由用户确认源码修复。重建后再次在两侧打开弹窗，验证右侧名称变为 `Print ticket`、左侧仍无名，并检查关闭后焦点回到触发控件。AI 测试使用本地模拟模型，网站与修复验证运行在真实 Chrome 中。

## Mac 验收记录

Chrome 157.0.8103.39 上，类型检查、生产构建、35 项回归和校园端到端专项全部通过。实时专项记录 28 个操作，其中 25 个确认两侧匹配，其余包含预期失配或关闭同步的操作。实际复现了 V0 弹窗焦点未进入和 Tab 移至弹窗外，确认修复后的票务按钮有可访问名称，关闭弹窗后焦点返回触发控件。专项还验证了跨账号请求被拒、关闭后会话失效，以及测试项目导出和原版本保留。校园专项验证四种入口和两种 URL 模式。工作区切换前完成 SQLite 备份与完整性校验，切换前后均为 81 个项目、145 个版本。
